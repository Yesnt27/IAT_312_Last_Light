# Lighthouse adventure game (Unity)

Instructions for Claude Code working in this project. Claude reads this file at the start of every session.

## Project facts
- Unity 6 (6000.6.2f1). 2D side-view so far (2D Sprite + Tilemap packages, Rigidbody2D). The 3D parts are not decided yet.
- Rendering: URP with the 2D Renderer (`Assets/Settings/Rendering/URP-2D.asset`, used by Graphics and every Quality level). Every scene has a `Global Light 2D`, an orthographic `Main Camera` with post-processing on, and a `Global Volume` using `GlobalVolumeProfile.asset` (Vignette + Color Adjustments, both neutral, for the sanity effect later). Sprites need `Sprite-Lit-Default` to react to 2D lights. Don't add 3D `Light` components.
- Input: the new Input System, asset `Assets/Scripts & Controllers/Input Action/PlayerControls.inputactions`. Its action map is `Controls`: `Move` (A/D), `Jump` (Space/W), `Interact` (E), `Dialogue` (Enter, advances dialogue and closes cutscene cards), `Click` (left mouse button), `Point` (mouse position). **Generate C# Class is off**, so there is no `PlayerControls` class. Scripts take `[SerializeField] private InputActionReference xAction;` fields, call `xAction.action.Enable()` in `OnEnable`, and only unsubscribe (never `Disable()`) in `OnDisable`, because actions are shared between scripts. Assign the references on the prefab (Player, Systems) by dragging the action sub-asset from the `.inputactions` file.
- Unity 6 physics API: use `rb.linearVelocity`, not `rb.velocity`.
- Scripts go in `Assets/Scripts & Controllers/`, grouped in subfolders by system (`Dialogue Stuff/` is the existing example).
- Art goes in `Assets/Visual Assets/`.
- Scenes are in `Assets/Scenes/`: Title Screen, HowToPlay, Outside, Basement, Floor 1–4, Top Lighthouse, Night Scene (3D), the cutscene scenes `Cut Scene 1 - Intro` and `Ending 1 - Win`, and Test Scene (a sandbox). Scenes must not have their own EventSystem (the Systems prefab has one; a second one spams "There are 2 event systems"), so the two cutscene scenes' EventSystems are switched off.
- **Systems prefab** (`Assets/Prefabs/Resources/Systems.prefab`): `Bootstrap` spawns it before the first scene loads and it is never destroyed, so Play works from any scene. Never place it in a scene. It holds `GameState` (flags, pages, day, power, task, night results; flag names in `GameFlags`), `SceneController` (`LoadScene(scene, spawnId)` with a fade), the EventSystem, and the UI canvas with `DialogueManager`, `TaskDisplay`, `InteractionPrompt`, `CutscenePlaceholder` and `ScreenFader`.
- **Player prefab** (`Assets/Prefabs/Player.prefab`): tagged `Player`, sprite on an `Art` child (the root scale is flipped for facing, so never scale the root), `PlayerController` + `PlayerInteractor`. Ground colliders go on the `groundLayer` layer. **Don't place it in scenes:** `SceneController` spawns it on every scene load at the spawn point a door asked for, or at the scene's Default spawn point when you press Play there. Scenes with no spawn points (Title Screen, Introduction) get no player. A Player placed by hand still works: it stays put on Play and is moved when a door sends you in.
- **Per scene:** `CameraManager` on the Main Camera, one `RoomBounds` (camera limits), and `SpawnPoint`s (one ticked **Is Default**, drawn as a green gizmo; the others are cyan) with ids that `SceneTransition`s point at. Naming: spawn ids say where you came from (`FromFloor1`, `FromOutside`). Day starts use `Outside/Dock` (Day 1) and `Floor 4/Bed` (Days 2–4, beside the bed the player sleeps in).
- **Environment prefabs** (`Assets/Prefabs/Environment/`): `Door` and `Stairs` (SceneTransition + trigger + Art + Label), `Spawn Point`, `Ground` (Art + Collision on groundLayer; scale the root to resize both), `Wall` (solid, not ground; disable Art for an invisible edge).
- **Room map** (every room is open on every day; only the basement is locked, by the `BasementKey` flag):
  `Outside ⇄ Floor 1 ⇄ Floor 2 ⇄ Floor 3 ⇄ Floor 4 ⇄ Top Lighthouse`, and `Floor 1 ⇄ Basement`. Each room has `Transitions` (doors/stairs) and `Spawn Points` folders; spawn ids are `From<Room>` (Floor 1 has `FromOutside`, `FromFloor2`, `FromBasement`; Floor 2 also has `Bed`).
- **Stairs between floors are walked, not pressed:** the Front Door / Basement Door (Floor 1) and Outside's Lighthouse Door are still E doors, but every floor-to-floor link is a touch zone (`SceneTransition` with `Load On Touch`, empty prompt, no art) in `Transitions`: `Stairs Up` sits near the top of the screen on the drawn up-staircase (Floor 1: x 2.66–4.5; Floors 2–4: left side, x ≈ −7.2…−5.2, bottom y above jump reach from the floor), `Stairs Down` at the right wall where the down-staircase meets the floor (x 8.4–10), the Basement's `Stairs Up` on its ladder. Each up-staircase art (`Floor 1 Stairs_0`, `Stair Up_0`) has a child `Walkable Steps`: an `EdgeCollider2D` along the step edges (45°) on **groundLayer** with a one-way `PlatformEffector2D` (Surface Arc 170). The first step is drawn 2–2.6 units above the floor: the player hops onto it and walks up, and walking along the floor passes **under** the stairs (Floor 1's basement door, Floor 4's bed). Arrival spawns sit beside the stairs, never inside a touch zone (Floors 2–4 `FromFloor<above>` stand on the up-staircase, `FromFloor<below>` at x ≈ 6.5); touches during a scene load are ignored so nobody bounces back. `PlayerInteractor` hides the E prompt for touch transitions. `PlayerController` swaps `Moving Material` (friction 0, combine Minimum) / `Standing Material` (friction 10, combine Maximum) in `Visual Assets/Materials/Physics/` so the player can climb the slope and doesn't slide when idle.
- **Starting the game:** `Title Screen` is first in Build Settings. Its Play button calls `UI/TitleMenu.Play()` → `DayManager.StartNewGame()` → DayManager's Intro cutscene, whose `Scene` = `Cut Scene 1 - Intro` (its `Story/Intro Dialogue` StoryTrigger plays the boat dialogue, then `Ends Cutscene`) → Day 1 at `Outside/Dock`. How To Play uses `TitleMenu.OpenHowToPlay()`, its Back button `TitleMenu.BackToTitle()`. **Never put a SceneController in a scene** (a second one takes over `SceneController.Instance` and breaks every load once its scene unloads); menus use TitleMenu. Pressing Play in Outside still starts a new game straight away (cutscene, then Day 1); Play in any other scene just spawns you there with no day running. DayManager's `Title Scene` = `Title Screen` (where the Death ending returns to). **Testing a later day:** DayManager's `Start On Day` (on the Systems prefab, Editor only) > 1 makes Play in Outside skip the intro and start that day, with every earlier day's Journal Page and Required Flags given (`DayManager.StartOnDay(day)`). So a day's Required Flags must include whatever later days need from it (Day 2 lists `BasementKey` and `Journal` for this). Keep it at 1.
- **Interactables:** subclass `Interaction/Interactable` (needs a trigger Collider2D). Its Inspector conditions (days, active tasks, required/hiding flags; checked by `Core/StoryConditions`) decide when the prompt shows, and `Unlock Flag` + `Locked Dialogue` make it locked; `When Tried While Locked` is a `StoryOutcome` applied after the locked line. Ready-made: `InteractDialogue`, `FlagPickup` (+ `After Pickup` outcome), `FoundPage` (+ `After Found`), `SceneTransition` (doors/stairs), `ElectricalBox`. Anything that should freeze the player uses `PlayerLock.Add/Remove`.
- **StoryOutcome** (`Core/StoryOutcome.cs`): optional new task (id + text) and/or flag, applied after a dialogue/pickup finishes. The task is set first, then the flag.
- **StoryTrigger** (`Interaction/`): a beat that plays by itself. `When In Scene` plays as soon as the player is in the scene and its conditions are met (re-checked whenever GameState changes); `On Player Enter` needs a trigger collider. It waits for fades, cards and other dialogue, then plays its dialogue and applies its outcome. `Remember As Flag` = only once per game. Put them in a scene's `Story` folder. **Then (optional):** `Ends Cutscene` hands control back to DayManager (for a cutscene scene it played); or `Load Scene` + `Load Spawn Id` loads another scene after the dialogue.
- **Cutscene scenes:** every `CutsceneCard` (DayManager's Intro/Ending/Victory/Death, each Day asset's Bedtime) has an optional `Scene`. Empty = the text card; set = `DayManager.PlayCutscene` loads that scene and waits until a StoryTrigger there with `Ends Cutscene` finishes (→ `DayManager.FinishCutscene()`), then the story continues (e.g. Day 1 loads). The scene must be in Build Settings and needs no spawn points/player.
- **ShowWhenAvailable** (`Interaction/`): hides an Interactable's renderers while it isn't available (the bottle only exists on Day 3, the key only during the key task). Hidden clickables can't be clicked.
- **Wire puzzle** (`Puzzles/`): `Assets/Prefabs/UI/Wire Puzzle.prefab` is a full-screen overlay with its own canvas (sorting 150): `WirePuzzle` shuffles 4 colours each open; drag a `WireDragEnd` (left plug) onto the `WireSocket` of the same colour (right). `WireDragEnd.TryConnect(socket)` does the connecting (tests call it directly). `ElectricalBox` spawns the prefab: first open collects its journal page, then the puzzle; solving sets `Solved Flag` (PowerFixed), turns the power on and plays `Solved Dialogue`.
- **Power lighting:** `Lighting/PowerLighting` on Systems dims each scene's Global Light 2D to 0.3 while `GameState.PowerOn` is false, except Outside/Title/Introduction.
- **Click to interact:** add `ClickToInteract` next to any Interactable to use it with the mouse instead of E. No collider is needed: the clickable area is its sprite(s). Hovering tints it and shows `[Click] <Prompt Text>`. It still obeys the Interactable's day/task/flag conditions, and E ignores it. `Max Distance From Player` 0 = clickable from anywhere on screen. `ClickInteractor` on Systems does the mouse lookup. Journal pages use this: `Assets/Prefabs/Interactables/Journal Page.prefab` (FoundPage + ClickToInteract; set `Page Number` and `Active On Days`). Simulated mouse input over MCP doesn't reach the game unless the Game view has focus, so test hover/click by hand.
- `DialogueManager.StartDialogue(dialogue, onComplete)`: a line with an empty character name shows no speaker (use for sound cues like *\*Static\**). Starting a dialogue while another is open replaces it, so wait a frame and for `isDialogueActive` to clear before chaining.
- **Day loop** (`Day Flow/`): `DayManager` (on Systems) runs wake → day puzzle → explore → night → bedtime → next day → ending. Each day is a `DayDefinition` asset in `Assets/Data/Days/` (start scene/spawn, power outage, wake dialogue, puzzle task, journal page, ship count, bedtime card); the day count is the length of the list on DayManager. The day puzzle ends when that day's journal page is collected **and** every flag in the Day asset's `Required Flags` is set. Page 0 = no page needed. Task ids DayManager sets: `go_to_lighthouse`, `night_shift`, `go_to_bed`. Arriving in DayManager's `Start Night When Entering` scene (Top Lighthouse) after the puzzle starts the night, which fades into DayManager's `Night Shift Scene` (the 3D `Night Scene`, in Build Settings). There, `Night/NightShift` shows only tonight's ships, plays its optional start line, then starts a clock (`First Night Seconds` 30 + `Extra Seconds Per Night` 15 per later night: 30/45/60/75 s), shown as `TIME LEFT 0:27` top-right on the `Binocular HUD` (`Night Timer`, red under 10 s; it pauses while PlayerLock is on). It counts reports in the task box; when every ship tonight is reported, or the clock runs out (`TIME'S UP`, player frozen for `End Delay` 2 s; unreported ships don't count, they're only listed as "Not reported in time" via `GameState.ShipsNotReported`), it calls `DayManager.FinishNightShift()` → night report card → back in 2D at DayManager's `After Night Scene` / `After Night Spawn Id` (`Floor 4` / `Bed`, beside the bed) with phase Bedtime, the `go_to_bed` task and `After Night Dialogue` → the player presses E on Floor 4's `Bed` (trigger over the bed art) → fade → bedtime card → next day, waking at the same bed (Floor 4/Bed). The `Bed` is only usable (and only shows `[E] Sleep`) during the `go_to_bed` task. Empty After Night Scene (or the DayDebugStart test flow) = straight to the morning as before. See **Ship spotting** below. If `Night Shift Scene` is empty, `Skip Night For Testing` shows a NIGHT card instead. `NightShiftStart` (lamp controls) and `Bed` still work when the skip is off. `CutscenePlaceholder.Show(...)` shows "CUTSCENE:" cards, `ShowCard(...)` plain cards.

- **3D night scene** (`Assets/Scenes/Night Scene.unity`, in Build Settings, loaded by the day loop for the night shift): the `3D Scene` model (a `.glb`, imported with glTFast) is the lamp room. Floor at y 5.21, round walls 7.58 m from (3.85, 0); MeshColliders were added to its 15 big meshes (prefab overrides in the scene). `First Person Player` = CharacterController (height 2 m) + `First Person/FirstPersonController` (WASD walk, mouse look, Space jump only when grounded (`Jump Height` 1 m), cursor captured; Esc frees it, clicking recaptures; freezes while PlayerLock is on) with the Main Camera as a child at 1.8 m (eye height = the camera's local Y). `Play Area` (radius 7.1) is a backup limit. 3D scenes must use the **3D renderer**: the camera's Renderer = index 1 (`URP-3D_Renderer`) on `URP-2D.asset`; 2D scenes stay on index 0. 3D lights and URP/Lit (glTF) materials are fine there. Input map `FirstPerson`: `Move` (WASD/arrows), `Look` (mouse delta), `Jump` (Space), `Interact` (E), `Use` (left mouse), `Select` (right mouse), `ReportFake` (Q), `ReportReal` (E). Scenes without SpawnPoints don't get the 2D player. `FirstPersonController.IsLookingAt(collider, reach)` = is the middle of the view on that collider (use trigger colliders as "look here" zones); `CanWalk` / `LookSensitivityScale` are set by the binoculars.

Camera far plane 5000.
- **Night lighting** (Night Scene, saved with the scene's Lighting settings): the sky is `Visual Assets/Materials/Night Sky.mat` (hand-written shader `Visual Assets/Shaders/Night Sky.shader`, "Lighthouse/Night Sky": dark zenith, bright `Horizon Glow Colour` band (0.72, 0.79, 0.87), `Glow Height`/`Fall-off`, optional stars; `Below The Horizon` = the fog colour). The old daylight `Sky.mat` is unused but kept. Fog = the glow colour, linear 500–2800 m, so the far sea fades into the glow while ships (≤ 410 m) get none. Ambient = Trilight, very dark (sky 0.035/0.045/0.08); reflection intensity 0.15. `Directional Light` = faint moonlight (0.55, 0.63, 0.85) × 0.08. `Lamp Room Light` = warm point light (intensity 6, range 11) under the ceiling so the desk and buttons stay visible. `Ocean.mat` is dark, and its horizon reflection only shows on reflections pointing at the horizon (`Horizon Reflection Sharpness` 12, ocean `Horizon` colour 0.3). The ocean shader now takes **spotlights/point lights** (`Water Colour In Spotlights`), so a beam shows on the water. **`Spot Light`** (the user's lighthouse beam, at (4.2, 32.7, −1.4), `Night/RotateLight` sweeps it 50°/s): URP lights fade with distance², so it needs Intensity **150000** and Range **900** to light ships 230–410 m out (intensity 1 / range 416 reached nothing). Unlit ships are near-black silhouettes; lit ones show fully. The Spot Light also has `Night/Searchlight` (which ships are inside its cone + range) and a child `Beam` = `Night/LightBeam` (ExecuteAlways: builds a cone mesh matching the light's Spot Angle, `Length` 600 m, `Strength` 0.35, colour from the light) with `Light Beam.mat` (shader `Visual Assets/Shaders/Light Beam.shader`, additive, soft edges, fades along the beam). URP has no volumetric light, so this is the visible shaft. The light sits high (y 32.7) on purpose: from there its cone clears the island's spires but still reaches the ships at sea level.

## Code style
Match `PlayerController.cs`: use `[Header]` groups, keep fields `[SerializeField] private`, use camelCase for fields and PascalCase for methods, and add few comments. Prefer small single-purpose MonoBehaviours over large managers.

## Unity MCP workflow (MCP for Unity, server "UnityMCP")
The Unity Editor must be open with the MCP server running (Window > MCP for Unity > Start Server).

1. **Check the connection first.** At the start of a task, call `manage_editor` or `manage_scene` (get active scene) to confirm Unity responds and the right scene is open.
2. **Scripts: write the file, then compile.** Create and edit `.cs` files directly on disk (or with `manage_script`). Then call `refresh_unity` and check `read_console` for compile errors. Do not attach a component until the code compiles cleanly.
3. **Scene objects: use the MCP tools.** Use `manage_gameobject`, `manage_components`, `manage_prefabs`, and `manage_ui` to create objects, add components, and assign serialized references. Never hand-edit `.unity`, `.prefab`, or `.asset` YAML.
4. **Reuse through prefabs.** Anything placed in more than one scene (the player, the dialogue UI, interactables) becomes a prefab under `Assets/Prefabs/`.
5. **Save and verify.** Save the scene with `manage_scene`. Re-read the hierarchy or components to confirm the change. Check `read_console` again after entering Play mode if behavior was changed.
6. **Experiment in Test Scene.** Try new mechanics in `Test Scene`, then move them into story scenes once they work.
7. **Commit at checkpoints.** Ask before committing. Scene changes are hard to diff, so commit before large scene edits.
