# Lighthouse adventure game (Unity)

Instructions for Claude Code working in this project. Claude reads this file at the start of every session.

## Project facts
- Unity 6 (6000.6.2f1). 2D side-view so far (2D Sprite + Tilemap packages, Rigidbody2D). The 3D parts are not decided yet.
- Rendering: URP with the 2D Renderer (`Assets/Settings/Rendering/URP-2D.asset`, used by Graphics and every Quality level). Every scene has a `Global Light 2D`, an orthographic `Main Camera` with post-processing on, and a `Global Volume` using `GlobalVolumeProfile.asset` (Vignette + Color Adjustments, both neutral, for the sanity effect later). Sprites need `Sprite-Lit-Default` to react to 2D lights. Don't add 3D `Light` components.
- Input: the new Input System, asset `Assets/Scripts & Controllers/Input Action/PlayerControls.inputactions`. Its action map is `Controls`: `Move` (A/D), `Jump` (Space/W), `Interact` (E), `Dialogue` (Enter, advances dialogue and closes cutscene cards), `Click` (left mouse button), `Point` (mouse position). **Generate C# Class is off**, so there is no `PlayerControls` class. Scripts take `[SerializeField] private InputActionReference xAction;` fields, call `xAction.action.Enable()` in `OnEnable`, and only unsubscribe (never `Disable()`) in `OnDisable`, because actions are shared between scripts. Assign the references on the prefab (Player, Systems) by dragging the action sub-asset from the `.inputactions` file.
- Unity 6 physics API: use `rb.linearVelocity`, not `rb.velocity`.
- Scripts go in `Assets/Scripts & Controllers/`, grouped in subfolders by system (`Dialogue Stuff/` is the existing example).
- Art goes in `Assets/Visual Assets/`.
- Scenes are in `Assets/Scenes/`: Title Screen, Introduction, Outside, Basement, Floor 1–4, Top Lighthouse, and Test Scene (a sandbox).
- **Systems prefab** (`Assets/Prefabs/Resources/Systems.prefab`): `Bootstrap` spawns it before the first scene loads and it is never destroyed, so Play works from any scene. Never place it in a scene. It holds `GameState` (flags, pages, day, power, task, night results; flag names in `GameFlags`), `SceneController` (`LoadScene(scene, spawnId)` with a fade), the EventSystem, and the UI canvas with `DialogueManager`, `TaskDisplay`, `InteractionPrompt`, `CutscenePlaceholder` and `ScreenFader`.
- **Player prefab** (`Assets/Prefabs/Player.prefab`): tagged `Player`, sprite on an `Art` child (the root scale is flipped for facing, so never scale the root), `PlayerController` + `PlayerInteractor`. Ground colliders go on the `groundLayer` layer. **Don't place it in scenes:** `SceneController` spawns it on every scene load at the spawn point a door asked for, or at the scene's Default spawn point when you press Play there. Scenes with no spawn points (Title Screen, Introduction) get no player. A Player placed by hand still works: it stays put on Play and is moved when a door sends you in.
- **Per scene:** `CameraManager` on the Main Camera, one `RoomBounds` (camera limits), and `SpawnPoint`s (one ticked **Is Default**, drawn as a green gizmo; the others are cyan) with ids that `SceneTransition`s point at. Naming: spawn ids say where you came from (`FromFloor1`, `FromOutside`). Day starts use `Outside/Dock` and `Floor 2/Bed`.
- **Environment prefabs** (`Assets/Prefabs/Environment/`): `Door` and `Stairs` (SceneTransition + trigger + Art + Label), `Spawn Point`, `Ground` (Art + Collision on groundLayer; scale the root to resize both), `Wall` (solid, not ground; disable Art for an invisible edge).
- **Room map** (every room is open on every day; only the basement is locked, by the `BasementKey` flag):
  `Outside ⇄ Floor 1 ⇄ Floor 2 ⇄ Floor 3 ⇄ Floor 4 ⇄ Top Lighthouse`, and `Floor 1 ⇄ Basement`. Each room has `Transitions` (doors/stairs) and `Spawn Points` folders; spawn ids are `From<Room>` (Floor 1 has `FromOutside`, `FromFloor2`, `FromBasement`; Floor 2 also has `Bed`). Floors 2–4 go down via their left door and up via `Stairs Up` on the right.
- **Starting the game:** Outside is first in Build Settings. Pressing Play in Outside starts a new game (DayManager → `New Game On Play In First Scene`): intro card, then Day 1 at `Outside/Dock`. Pressing Play in any other scene just spawns you there with no day running. The title screen isn't used yet: DayManager's `Title Scene` is empty, so after the ending a new game starts.
- **Interactables:** subclass `Interaction/Interactable` (needs a trigger Collider2D). Its Inspector conditions (days, active tasks, required/hiding flags; checked by `Core/StoryConditions`) decide when the prompt shows, and `Unlock Flag` + `Locked Dialogue` make it locked; `When Tried While Locked` is a `StoryOutcome` applied after the locked line. Ready-made: `InteractDialogue`, `FlagPickup` (+ `After Pickup` outcome), `FoundPage` (+ `After Found`), `SceneTransition` (doors/stairs), `ElectricalBox`. Anything that should freeze the player uses `PlayerLock.Add/Remove`.
- **StoryOutcome** (`Core/StoryOutcome.cs`): optional new task (id + text) and/or flag, applied after a dialogue/pickup finishes. The task is set first, then the flag.
- **StoryTrigger** (`Interaction/`): a beat that plays by itself. `When In Scene` plays as soon as the player is in the scene and its conditions are met (re-checked whenever GameState changes); `On Player Enter` needs a trigger collider. It waits for fades, cards and other dialogue, then plays its dialogue and applies its outcome. `Remember As Flag` = only once per game. Put them in a scene's `Story` folder.
- **ShowWhenAvailable** (`Interaction/`): hides an Interactable's renderers while it isn't available (the bottle only exists on Day 3, the key only during the key task). Hidden clickables can't be clicked.
- **Wire puzzle** (`Puzzles/`): `Assets/Prefabs/UI/Wire Puzzle.prefab` is a full-screen overlay with its own canvas (sorting 150): `WirePuzzle` shuffles 4 colours each open; drag a `WireDragEnd` (left plug) onto the `WireSocket` of the same colour (right). `WireDragEnd.TryConnect(socket)` does the connecting (tests call it directly). `ElectricalBox` spawns the prefab: first open collects its journal page, then the puzzle; solving sets `Solved Flag` (PowerFixed), turns the power on and plays `Solved Dialogue`.
- **Power lighting:** `Lighting/PowerLighting` on Systems dims each scene's Global Light 2D to 0.3 while `GameState.PowerOn` is false, except Outside/Title/Introduction.
- **Click to interact:** add `ClickToInteract` next to any Interactable to use it with the mouse instead of E. No collider is needed: the clickable area is its sprite(s). Hovering tints it and shows `[Click] <Prompt Text>`. It still obeys the Interactable's day/task/flag conditions, and E ignores it. `Max Distance From Player` 0 = clickable from anywhere on screen. `ClickInteractor` on Systems does the mouse lookup. Journal pages use this: `Assets/Prefabs/Interactables/Journal Page.prefab` (FoundPage + ClickToInteract; set `Page Number` and `Active On Days`). Simulated mouse input over MCP doesn't reach the game unless the Game view has focus, so test hover/click by hand.
- `DialogueManager.StartDialogue(dialogue, onComplete)`: a line with an empty character name shows no speaker (use for sound cues like *\*Static\**). Starting a dialogue while another is open replaces it, so wait a frame and for `isDialogueActive` to clear before chaining.
- **Day loop** (`Day Flow/`): `DayManager` (on Systems) runs wake → day puzzle → explore → night → bedtime → next day → ending. Each day is a `DayDefinition` asset in `Assets/Data/Days/` (start scene/spawn, power outage, wake dialogue, puzzle task, journal page, ship count, bedtime card); the day count is the length of the list on DayManager. The day puzzle ends when that day's journal page is collected **and** every flag in the Day asset's `Required Flags` is set. Page 0 = no page needed. Task ids DayManager sets: `go_to_lighthouse`, `night_shift`, `go_to_bed`. Arriving in DayManager's `Start Night When Entering` scene (Top Lighthouse) after the puzzle starts the night; `Skip Night For Testing` (on) shows a NIGHT card, then bedtime card, then the next day (no bed needed). `NightShiftStart` (lamp controls) and `Bed` still work when the skip is off. `CutscenePlaceholder.Show(...)` shows "CUTSCENE:" cards, `ShowCard(...)` plain cards.
- **The story so far** (task ids in brackets):
  - Day 1 (Outside/Dock): explore [`day1_explore`] → trying the locked Basement Door (Floor 1) → [`day1_find_key`] → `Basement Key` on Floor 4 (only during that task) → [`day1_open_basement`] → entering the Basement (StoryTrigger) → [`day1_food_journal`] → `Food` (flag FoodFound) + `Journal` (page 1, flag Journal) → top of the lighthouse. Day 1 needs page 1 + FoodFound.
  - Day 2 (Floor 2/Bed, power out): [`day2_power`] → `Electrical Box` in the Basement (page 2 + wire puzzle → PowerFixed) → top. Needs page 2 + PowerFixed.
  - Day 3 (Floor 2/Bed): horn [`day3_check_horn`] → arriving Outside (StoryTrigger) → [`day3_observe_water`] → `Message in a Bottle` (flag BottleMessage) → [`day3_find_book`] → Floor 3 bookshelf, `Book - Strange Symbols` (flag BottleDeciphered) → [`day3_use_message`]. Stops here: the safe (page 3) isn't built, so Day 3 can't finish yet.
  - Day 4 is an empty placeholder asset. `DayDebugStart` in a test scene runs the loop there without loading story scenes (Test Scene has one; disable it to test other things).
- **3D night scene** (`Assets/Scenes/Night Scene.unity`, not in Build Settings yet and not hooked to the day loop yet): the `3D Scene` model (a `.glb`, imported with glTFast) is the lamp room. Floor at y 5.21, round walls 7.58 m from (3.85, 0); MeshColliders were added to its 15 big meshes (prefab overrides in the scene). `First Person Player` = CharacterController (height 2 m) + `First Person/FirstPersonController` (WASD walk, mouse look, Space jump only when grounded (`Jump Height` 1 m), cursor captured; Esc frees it, clicking recaptures; freezes while PlayerLock is on) with the Main Camera as a child at 1.8 m (eye height = the camera's local Y). `Play Area` (radius 7.1) is a backup limit. 3D scenes must use the **3D renderer**: the camera's Renderer = index 1 (`URP-3D_Renderer`) on `URP-2D.asset`; 2D scenes stay on index 0. 3D lights and URP/Lit (glTF) materials are fine there. Input map `FirstPerson`: `Move` (WASD/arrows), `Look` (mouse delta), `Jump` (Space). Scenes without SpawnPoints don't get the 2D player.
- **Night Scene ocean & windows:** the model's walls had no openings, so the `Cylinder` MeshFilter shows `Assets/Visual Assets/Generated/Lamp Room Wall (windows).asset` (a copy with the inner wall cut away between y 6.5 and 10.8); its MeshCollider still uses the original solid mesh, so the player stays inside. `Window Frames` = 12 posts; `Tower Base` = placeholder column under the model. `Ocean` (y −25, 30 m below the floor) = `Environment/OceanSurface` (builds a 6 km grid mesh at runtime/edit time, dense near the tower) + `Visual Assets/Materials/Ocean.mat` using the hand-written URP shader `Visual Assets/Shaders/Ocean.shader` ("Lighthouse/Ocean": 4 Gerstner waves + ripples, sky reflection, sun glint, crest foam, fog; all tweakable on the material). Scene fog (linear 250–2600 m) and `Sky.mat` (procedural, ground colour = fog colour) blend the horizon; camera far plane 5000.
- **Night Scene island:** `Island Terrain` is a generated Unity terrain (`Visual Assets/Generated/Island/Island Terrain.asset`, 600×600 m terrain, heightmap 1025, origin (−296.15, −32, −430)). The island is small, jagged and ominous: ~200 m across, centred at (3.85, −48) just south of the lighthouse, ridged rock, 6 spires (highest point 26 m above the sea, below the lamp room), sea cliffs all round. The lighthouse stands on a flat pad at y −15 (10 m above the sea at −25). Painted ~96% rock/cliff, a few grass patches, near-black gravel shore, using 4 TerrainLayers (Sand, Grass, Cliff, Mossy Rock) made from the Free Island Collection textures and darkened with each layer's Diffuse Remap Max; material = URP Terrain Lit. **Terrain data .asset files are binary**: `.gitattributes` marks the island's (and the pack's) as `binary`, because the template's `*.asset` text rule corrupted the first island file. Add a `binary` line for any new terrain asset folder. The Free Island Collection's own terrains/scenes were saved by Unity 5.6 and **can't load in Unity 6** ("Serialized files before 2019.1 are deprecated"); only its textures are used. The user's earlier `Island` object is switched off.
- **2D player facing:** `PlayerController.Face` flips only the sign of X, so a Player scaled to fit its art keeps its size. Still better to size the art on the `Art` child (or the prefab) so every scene's auto-spawned player matches.
- Placeholder art uses `Assets/Visual Assets/Placeholders/Square.png`, never sprites from a package `Editor` folder (those are stripped from builds).
- These are empty stubs waiting to be implemented: `Basement`, `Safe`, `Journal`, `MessageInaBottle` (the bottle currently uses `InteractDialogue`).
- Testing over MCP: Play mode only advances while the Unity window has focus. If `Time.frameCount` stops moving, bring Unity to the front.

## Code style
Match `PlayerController.cs`: use `[Header]` groups, keep fields `[SerializeField] private`, use camelCase for fields and PascalCase for methods, and add few comments. Prefer small single-purpose MonoBehaviours over large managers.

## Unity MCP workflow (MCP for Unity, server "UnityMCP")
The Unity Editor must be open with the MCP server running (Window > MCP for Unity > Start Server).

1. **Check the connection first.** At the start of a task, call `manage_editor` or `manage_scene` (get active scene) to confirm Unity responds and the right scene is open.
2. **Scripts: write the file, then compile.** Create and edit `.cs` files directly on disk (or with `manage_script`). Then call `refresh_unity` and check `read_console` for compile errors. Do not attach a component until the code compiles cleanly.
3. **Scene objects: use the MCP tools.** Use `manage_gameobject`, `manage_components`, `manage_prefabs`, and `manage_ui` to create objects, add components, and assign serialized references. Never hand-edit `.unity`, `.prefab`, or `.asset` YAML.
4. **Reuse through prefabs.** Anything placed in more than one scene (the player, the dialogue UI, interactables) becomes a prefab under `Assets/Prefabs/`.
5. **Save and verify.** Save the scene with `manage_scene`. Re-read the hierarchy or components to confirm the change. Check `read_console` again after entering Play mode if behavior was changed.
6. **Experiment in Test Scene.** Try new mechanics in `Test Scene`, then move them into story scenes once they work.
7. **Commit at checkpoints.** Ask before committing. Scene changes are hard to diff, so commit before large scene edits.
